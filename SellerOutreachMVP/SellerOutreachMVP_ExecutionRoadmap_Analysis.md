# SellerOutreachMVP_ExecutionRoadmap_Analysis

## 목적
- 설계 문서를 실제 개발 착수용 단계별 실행 계획으로 압축한다.
- 무엇을 먼저 만들고, 각 단계에서 어디까지 완성해야 하는지 명확히 한다.

## 제품 한 줄 정의
- 공개 판매자 후보를 찾고, 점수화와 사람 검수를 거쳐 안전하게 아웃리치하고, 답장 이후 CRM과 아마존 온보딩으로 이어지는 내부 운영 도구

## 개발 전략
- 자동화보다 내부 운영 흐름을 먼저 완성한다.
- 외부 연동보다 설정, 상태, 이력 저장을 먼저 만든다.
- 운영자가 직접 기준을 바꿀 수 있는 설정형 구조를 우선한다.
- 각 단계는 실제 운영 시나리오가 끝까지 이어지는지를 기준으로 완료 판단한다.

## 선결정 항목
- 첫 타겟 카테고리
- 첫 타겟 플랫폼
- 이메일 우선인지 DM 우선인지
- 절대 제외할 카테고리/계정
- 성공 기준을 어디까지로 볼지

## 권장 단계
### Phase 0. 범위 확정
- 목표: 운영 기준과 성공 기준을 먼저 고정한다.
- 할 일
  - 첫 카테고리와 플랫폼을 결정한다.
  - 아웃리치 우선 채널을 결정한다.
  - 제외 조건과 금지 대상을 정리한다.
  - CRM 단계 이름과 온보딩 종료 기준을 정한다.
- 산출물
  - 의사결정 체크리스트 확정본
  - 초기 캠페인 기준표 초안
  - 점수표 초안
  - 검수 체크리스트 초안
- 완료 기준
  - 운영자가 "이 기준이면 첫 리드를 검수할 수 있다"라고 판단할 수 있다.

### Phase 1. 기반 구축
- 목표: 이후 기능 구현이 흔들리지 않도록 프로젝트 골격과 데이터 계약을 고정한다.
- 할 일
  - 프로젝트 부트스트랩
  - DB 연결과 마이그레이션 구성
  - 핵심 상태값과 테이블 정의
  - DTO와 에러 응답 규칙 확정
  - 기본 인증/권한 구조 방향 정리
- 산출물
  - 초기 프로젝트 구조
  - PostgreSQL 마이그레이션
  - API/DTO 초안
  - 공통 응답 포맷
- 완료 기준
  - 캠페인, 리드, 점수, 검수, 아웃리치, CRM, 온보딩의 핵심 테이블과 상태값이 코드로 표현되어 있다.

### Phase 2. 설정 도메인 구현
- 목표: 운영자가 코드를 건드리지 않고 기준을 관리할 수 있게 한다.
- 할 일
  - 캠페인 CRUD
  - 후보 소스 CRUD
  - 필터 CRUD
  - 점수 규칙 세트/항목 CRUD
  - 체크리스트 템플릿/항목 CRUD
- 화면
  - 설정 페이지
  - 캠페인 폼
  - 규칙 폼
  - 체크리스트 폼
- 완료 기준
  - 운영자가 첫 캠페인 기준을 화면에서 입력하고 수정할 수 있다.

### Phase 3. 리드 저장/조회 구현
- 목표: 후보 데이터를 안정적으로 쌓고 운영자가 찾을 수 있게 한다.
- 할 일
  - 리드 등록 API
  - 리드 목록 조회 API
  - 리드 상세 조회 API
  - 연락처/게시물/기본 상태 저장
  - 중복 방지 규칙 적용
- 화면
  - 리드 리스트
  - 리드 상세
  - 필터 사이드바
  - 빠른 요약 패널
- 완료 기준
  - 운영자가 특정 캠페인에서 후보를 검색하고 상세 정보를 확인할 수 있다.

### Phase 4. 점수 계산과 검수 구현
- 목표: 운영 판단이 가능한 핵심 흐름을 완성한다.
- 할 일
  - 리드 점수 계산
  - 점수 근거 저장/조회
  - 검수 체크리스트 입력
  - 승인/보류/제외 처리
  - `DO_NOT_CONTACT` 및 발송 제한 규칙 반영
- 화면
  - 점수 패널
  - 검수 패널
  - 검수 큐
- 완료 기준
  - `수집 -> 점수화 -> 검수` 흐름이 끊기지 않고 동작한다.
  - 승인되지 않은 리드는 발송 단계로 넘어갈 수 없다.

### Phase 5. 아웃리치 큐 구현
- 목표: 사람 승인 기반의 안전한 발송 준비 흐름을 만든다.
- 할 일
  - 메시지 초안 미리보기
  - 메시지 승인
  - 이메일 발송 처리
  - DM 수동 큐 등록
  - 후속 대기 상태 관리
- 화면
  - 아웃리치 큐
  - 이메일 탭
  - DM 탭
  - 후속 대기 탭
- 완료 기준
  - 승인된 리드만 이메일 또는 DM 처리 대상으로 올라온다.
  - 발송 기록과 상태가 남는다.

### Phase 6. CRM과 답장 관리 구현
- 목표: 첫 접촉 이후 운영 흐름을 이어 붙인다.
- 할 일
  - 답장 등록/재분류
  - CRM 단계 이동
  - 활동 메모 기록
  - 관심도와 후속 일정 관리
- 화면
  - CRM 보드
  - 활동 로그
  - 답장 상세/분류 UI
- 완료 기준
  - `발송 -> 답장 -> CRM 이동` 흐름이 화면에서 이어진다.

### Phase 7. 온보딩 구현
- 목표: 관심 셀러를 실제 실행 단계까지 관리한다.
- 할 일
  - 온보딩 시작
  - 온보딩 상태 업데이트
  - 메모와 다음 액션 저장
  - 체크리스트 관리
- 화면
  - 온보딩 상세
  - 체크리스트
  - 메모 패널
  - 다음 액션 영역
- 완료 기준
  - CRM에서 온보딩으로 넘어간 셀러의 진행 상황을 추적할 수 있다.

### Phase 8. 운영 가시성 강화
- 목표: 실무 운영 효율과 추적 가능성을 높인다.
- 할 일
  - 대시보드 KPI
  - 오늘 할 일
  - 최근 답장
  - 감사 로그
  - 운영 로그 고도화
- 완료 기준
  - 운영자가 우선순위와 병목을 대시보드에서 바로 확인할 수 있다.

## MVP 1차 완료 기준
- 운영자가 캠페인을 만들고 규칙을 설정할 수 있다.
- 리드가 `수집 -> 점수화 -> 검수 -> 발송 준비 -> CRM` 흐름으로 이동한다.
- 승인 전 발송 금지와 재연락 금지 대상 제어가 동작한다.
- 각 단계의 상태와 근거가 화면과 DB에 남는다.

- 리드 리스트/상세 기본 UI

- 대시보드
- 감사 로그
- 운영 편의 기능

## 구현 시 주의점
- 대량 자동 DM 발송은 MVP 범위 밖이다.
- 비공개 정보 수집은 하지 않는다.
- 점수는 숫자보다 근거 노출이 중요하다.
- 모든 핵심 판단은 나중에 추적 가능해야 한다.
- 설정 데이터와 운영 데이터는 분리한다.

## 바로 시작할 작업 패키지
1. `DDL + 상태 Enum + 인덱스` 확정
2. `Campaign / Rule / Checklist` API와 폼 구현
3. `Lead List / Lead Detail` 구현
4. `Score / Review Queue` 구현
